## Contract

The contract is §17.1 read as a specification.

- **Traced per run** (F22 and F40 already require it, and the fields exist on `main` as `attempts`/`skipped` audit content in `src/platform/gateway/route.ts` and `call.ts`): tenant/domain, run id, expert and prompt versions, corpus/index generation, stage timings, tool counts and truncation, verifier outcome, provider and model per attempt, budget reservation and usage, output status. This packet reads them and does not redefine them, and provider/model identity **never** becomes employee-visible ([`src/contracts/chat.ts`](../../src/contracts/chat.ts) keeps `TierChangeReason` a closed enum for that reason).
- **One query per metric, one table per fact.** A view is a `SELECT` over the owning packet's tables. If a metric needs a field nobody records, that is a `needs-contract` request against the owning packet, not a column added here.
- **Alerts, the five §17.1 classes:** authorization anomalies, audit loss, budget failure, stale critical collections, stopped operational reminders — each with a rule, an owner-set threshold and a destination. **Model-chain (§17.1 v1.3):** per provider × task class — availability, latency, fallback rate with the reason F40 already records, verification pass rate, eval score by tier, cost per answered question, free-allowance burn; plus local-box uptime and OCR queue age. The three named alarms are: answers drifting to paid tiers beyond an owner-set share, the box offline longer than an owner-set window, and a tier's verification pass rate falling below its eval baseline.
- **Authorization of the read path.** An ops metric must not become a leak channel: views carry the same tenant scoping as the underlying tables, the content-rich audit views stay separate from ordinary logs and source-authorized (§17.1), and no `client_confidential` document, chunk detail, query string or eval case text crosses into a metric row or an alert message.
- **Kill switches (§17.1, M1 scope decided by [#74](https://github.com/TerraOI/TerraOI/issues/74)):** tenant, expert and provider as settings ([T-304](./T-304-kill-switch-provisioning.md)); the platform switch is the deployment rollback in [T-404](https://github.com/TerraOI/TerraOI/pull/191)'s runbook. This packet observes all of them and builds none.

Owed, not waived (§6a) — and the local dry run is labelled as what it is rather than traded for the staging one.
- [ ] negative: no view exposes prompt bodies, document text, signed URLs, object keys, provider names or personal prompts — shown by an explicit column list per view plus a test that looks for the forbidden shapes and finds none; the `secrets` CI job stays green. **Not ticked as written**, because there are no views yet. What does exist is the machine half over the *definitions*: `FORBIDDEN_OUTPUT_FIELDS` rejects a prompt body, personal prompt, document text, chunk text, query string, signed URL, object key, provider **name** (grouping is by `provider_id`), eval case text and any contact field in a metric's declared columns, and a second test tampers a metric with `prompt_body` and `signed_url` so the first test cannot pass by being vacuous. The view-level proof, and the `secrets` claim for this branch, wait on the migration.
- [ ] negative: another tenant's counts never appear, and a `client_confidential` corpus never surfaces in a metric row or an alert message. **Not ticked, and deliberately not approximated.** The definitions each declare `scoping.mode = organisation` and every metric's column list carries `organisation_id`, which is a precondition for the proof, not the proof: cross-tenant isolation is enforced by RLS on the views and shown by the pgTAP file that ships with the migration (the box above). A `client_confidential` corpus never appearing in an alert message is likewise a property of the alert *body*, which does not exist yet — the module only prints rule ids, verdicts and rule definitions, so no corpus text can reach it today, and that will need re-proving once a real message template exists.
- [ ] failure: an unreachable database, an expired credential or a missing table each yield `not_available` with a reason rather than an empty dashboard; a failed alert evaluation never disables the rule for the next run; a dead-lettered or stuck `extract` job is visible. Unticked until Round-1 is re-reviewed. Dead letter is defined by [#99](https://github.com/TerraOI/TerraOI/issues/99) / [ADR-0005 §10b](../decisions/0005-ocr-job-api-and-artifact-home.md) as `status = 'failed' AND last_error = 'retries_exhausted'` (other failures counted apart via `ingestion_failed_other`); replay under a new parser generation is **this packet** (T-405), deferred past M1. `metricValue` keeps absences apart (source unreachable; table not merged; owed `sourceColumns`; query not read) and returns `value: null` for each; a multi-metric rule with any non-ok input is `not_available` listing the missing inputs, never `ok`; a throwing predicate yields `evaluation_error` and keeps the rule enabled. Extract-stage age only counts `status in ('queued','leased','running')` (wait clock on `updated_at` for requeues). The dry run refuses to exit 0 if any rule cannot be made to fire.
