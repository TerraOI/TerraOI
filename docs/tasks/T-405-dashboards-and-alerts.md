## Contract

The contract is §17.1 read as a specification.

- **Traced per run** (F22 and F40 already require it, and the fields exist on `main` as `attempts`/`skipped` audit content in `src/platform/gateway/route.ts` and `call.ts`): tenant/domain, run id, expert and prompt versions, corpus/index generation, stage timings, tool counts and truncation, verifier outcome, provider and model per attempt, budget reservation and usage, output status. This packet reads them and does not redefine them, and provider/model identity **never** becomes employee-visible ([`src/contracts/chat.ts`](../../src/contracts/chat.ts) keeps `TierChangeReason` a closed enum for that reason).
- **One query per metric, one table per fact.** A view is a `SELECT` over the owning packet's tables. If a metric needs a field nobody records, that is a `needs-contract` request against the owning packet, not a column added here.
- **Alerts, the five §17.1 classes:** authorization anomalies, audit loss, budget failure, stale critical collections, stopped operational reminders — each with a rule, an owner-set threshold and a destination. **Model-chain (§17.1 v1.3):** per provider × task class — availability, latency, fallback rate with the reason F40 already records, verification pass rate, eval score by tier, cost per answered question, free-allowance burn; plus local-box uptime and OCR queue age. The three named alarms are: answers drifting to paid tiers beyond an owner-set share, the box offline longer than an owner-set window, and a tier's verification pass rate falling below its eval baseline.
- **Authorization of the read path.** An ops metric must not become a leak channel: views carry the same tenant scoping as the underlying tables, the content-rich audit views stay separate from ordinary logs and source-authorized (§17.1), and no `client_confidential` document, chunk detail, query string or eval case text crosses into a metric row or an alert message.
- **Kill switches (§17.1, M1 scope decided by [#74](https://github.com/TerraOI/TerraOI/issues/74)):** tenant, expert and provider as settings ([T-304](./T-304-kill-switch-provisioning.md)); the platform switch is the deployment rollback in [T-404](./T-404-production-readiness.md)'s runbook. This packet observes all of them and builds none.

## Acceptance tests (write first)

- [ ] positive: the new pgTAP file — each view returns the expected row for one synthetic tenant, is **empty** for another tenant, and a `suspended` membership reads nothing; the scoped read RPC sets its scope as its first statement (FAQ-0011) and refuses a foreign `p_organisation_id`.
- [ ] positive: `scripts/ops-metrics.test.mjs` — the metric set is closed and named, one definition per §17.1 line, and a metric whose table is missing reports `not_available` naming the owning packet, **never** `0`. A zero that really means "no data" is the failure this packet exists to prevent: plan §8.2's "empty and failed are different answers", applied to operations.
- [ ] positive: `scripts/ops-metrics.test.mjs` — the four latency classes are separate metrics, so an ingestion-queue spike cannot be read as an interactive-latency spike (§14 measures them separately for the same reason).
- [ ] positive: alert dry-run on staging — each of the eight rules (five §17.1 classes + three chain alarms) fired once by a synthetic condition, each verdict recorded in the register with the rule id and the threshold used.
- [ ] negative: no view exposes prompt bodies, document text, signed URLs, object keys, provider names or personal prompts — shown by an explicit column list per view plus a test that looks for the forbidden shapes and finds none; the `secrets` CI job stays green.
- [ ] negative: another tenant's counts never appear, and a `client_confidential` corpus never surfaces in a metric row or an alert message.
- [ ] failure: an unreachable database, an expired credential or a missing table each yield `not_available` with a reason rather than an empty dashboard; a failed alert evaluation never disables the rule for the next run; a dead-lettered or stuck `extract` job is visible — [ADR-0005](../decisions/0005-ocr-job-api-and-artifact-home.md) records that one stuck job blocks a tenant's box until a human intervenes **and that no packet owns the dead letter** (U-3 in [BACKLOG.md](../BACKLOG.md)).
