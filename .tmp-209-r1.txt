**Blocking**

B1. `src/platform/retrieval/recall.ts:118-127`. Duplicate rows inflate recall. `found` counts every row in the top k whose id is expected, so for a case expecting `{C1, C2}`, a run returning `["C1", "C1"]` scores `foundInTopK: 2, recall: 1`. `Math.min(found, expected.size)` caps the number but not the error. For a harness whose job is to make an unearned number impossible, this is the hole. Fix: count distinct expected ids present, e.g. `const found = new Set(topK.filter((id) => expected.has(id))).size;`, and add a case with a duplicated id that expects `recall: 0.5`. Apply the same distinct count to `forbiddenRetrieved`, or document that it counts rows on purpose.
